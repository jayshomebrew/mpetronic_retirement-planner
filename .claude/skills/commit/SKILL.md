name: commit
description: Commit Rules
---

1. Review code changes to determine what to describe in the commit message. You do not have to
   prompt me for permission to run the necessary git commands to determine the content of the git
   commit message or to run git add or git commit commands.

2. Generate a commit message that must start with a single line title no more than 60 characters
   long. This must be followed by a blank line. Then the more detailed explanations of the commit
   can be included using a bullet format where the bullet character must be a dash followed by a
   space then there can be multiple sentences per bullet. These bullet blocks must be no more than
   74 characters and each line must end in a hard newline. Do not add extra blank lines between
   bullets.

3. Stop and let me review the proposed commit messages before you commit it and present me with a
   proceed button.

4. When I acknowledge the commit message, perform the commit but do not push the changes.

5. When you have created the proposed commit, present it to me like you do for implementation plans
   where you present me with a "proceed" and "open" button.

6. Do not use prefixes like "feat", "fix, etc., in commit titles. Just use a normal terse sentence.

# IMPORTANT

Review all submitted code for personal information and secrets and abort the commit and list the exact findings for the file and line number and actual text of what you discovered.
